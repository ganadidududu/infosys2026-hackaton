# PRD → 감사기준안 반영 계획

현재 `PRD.md`는 예시 기준(100점 감점제, 적정/한정 등급, 가상 조항 번호)을 쓰고 있다. 아래대로 `docs/감사기준안.md`에 맞춰 고친다. 조항 번호는 기준안 표기를 따른다(예: 3부 35조, 4부 23조).

## 1. 반드시 바꿀 것 (기준안과 충돌)

| 현재 PRD | 바꿀 내용 | 근거 |
| --- | --- | --- |
| 100점 시작 감점제 + 등급(90↑ 적정, 75~89 한정, 75↓ 부적정) | 등급 삭제. **총 감점 = 사례별 감점 합 + 경고 감점**. 사례별 감점은 기억의 동일 사례 처분을 그대로 적용하고, 선례가 없으면 "신규 유형: 감사인단 전원 논의"로 넘겨 비워 둔다. 경고 감점 = max(0, 경고 수 − 2) | 4부 23·24·26조 |
| 감사 판단 결과 = 점수·등급 | 감사의견 = 4가지 평가: ① 감사자료의 신뢰성 ② 회계관리 및 통제의 유효성 ③ 수입 및 지출의 종합적 적절성 ④ 회계 전반 | 4부 18조 |
| 예시: 과잠 공동구매에 별도 통장 개설 + 감사위원회 고지 | 별도 통장은 **축제 부스 운영에만** 허용. 사용 전 통장 사본을 감사위원회에 전달·승인받고, 별도 엑셀 장부·통장사본·과거거래내역서를 제출하며, 비정기감사를 요청할 수 있다. 과잠 공동구매는 학생회비 통장으로 수취하고 수입 구분(참가비/사업수익금)은 질의하도록 권장 | 3부 6·18~23조 |
| 예시 조항(제9조 증빙, 제12조 식비 한도, 제15조 정산 공개 등) | 기준안의 실제 조항으로 교체. 식비 1인 한도 같은 규칙은 기준안에 없으므로 삭제 | 기준안 전체 |
| 공개 페이지: 점수·등급 | 총 감점, 경고 횟수, 감점 사유·근거 조항, 감사의견 4가지 평가, **이의 내용과 답변(필수)**, 회계기간별 추이. 누구나 접근 가능하고 수정 불가 | 3부 70·71조, 4부 21·22조 |

## 2. 기능 1(영수증·감사자료)에 넣을 기준안 규칙

- **수입 구분** (3부 12조): 학생회비 / 참가비 / 사업수익금 / 예금결산이자 / 기타 / 취소(환급)
- **지출 구분** (3부 16조): 사업수행비 / 관리운영비 / 소모품비 / 감사비용 / 기타 / 취소(결제 취소)
- **사업번호** (3부 37·38조): 학생회비 0, 관리운영비 97, 소모품비 98, 사업무관거래 99, 감사비용 100은 고정. 나머지 사업은 발생 순서대로 1부터 부여
- **수입/지출내역서** (3부 49~55조): "(사업번호)-(일련번호)"(예: 2-7), 통장내역은 과거거래내역서 문구 그대로, 내용, 세목(영수증 표기 그대로, 지출 수수료는 별도 세목, 수입은 수수료 차감 순액), 지급방법, 증빙종류, 증빙서류
- **엑셀 장부** (3부 56~59조): 1시트 '사업목록', 2시트 '총거래장부'(첫 행은 전기 이월을 수입으로 기록, 이후 발생 순으로 일자·사업번호·통장내역·거래내용·수입/지출액·결제수단·비고, 현금흐름이 없는 전용 거래는 비고에 "현금의 유입과 유출이 없는 거래"). 3~5시트는 작성하지 않음
- **사업개요서** (3부 39~48조): 수입 총액과 지출 총액(교비 제외)은 자동, 대상·참가인원(집행부/전체)·사업내용·적요·비고는 집행부가 작성
- **증빙 요건** (3부 29~36조), OCR이 확인할 것:
  - 카드 지출: 세목이 표기된 카드 전표
  - 계좌이체 지출: 세목이 표기된 현금영수증
  - 예약금: 과거거래내역서 + 이체내역서
  - 비사업자 현금 지급: 표준/특수 영수증 + 이체내역서 + 과거거래내역서
  - 단체간거래: 과거거래내역서 + 이체내역서 + 단체간거래확인서
  - 세목 표기가 불가능한 업체: 총액 영수증 + 계산서 6항목(① 업체·책임자 이름·서명 ② 책임자 연락처 ③ 견적 산출 근거(세목) ④ 집행부 담당자 이름·서명·연락처 ⑤ 일자·수단·총액 ⑥ 문서 조작 법적 책임 경고와 담당자 서명)
  - 현금 수입: 표준/특수 영수증 + 과거거래내역서. 계약 수입은 계약서
- **회계총칙 검사** (3부 5~10·13·14·17조): 카드 결제 원칙, 할부 금지, 포인트 적립 금지(캐시백은 학생회비에 산입), 참가비 ≤ 해당 사업 지출, 수수료 처리
- **대사 방향** (2부 6.4): 지출은 역진법(모든 출금 → 증빙), 수입은 전진법(모든 입금 → 장부 기록·수입 구분). 어느 사업에도 안 붙은 입금은 "미분류 수입"으로 표시
- **이중감사 제한** (2부 7, 3부 22·23조): 비정기감사로 이미 수검한 증빙은 정기감사에서 제외(AuditedEvidence)

## 3. 기능 2(LLM 감사 판단) 수정

- 감사 패킷에 **해당 회계기간 질의·답변(Inquiry)**을 추가한다. 기준안과 같은 지위를 갖되, 충돌하면 기준안이 우선(4부 15조).
- 감사 LLM 출력 스키마: `clause, target, verdict(충족/미충족/확인 필요), evidence[{doc, quote}], missing[], same_case{case_id, why}, is_new_type, question`. **감점 점수는 출력하지 않는다.**
- 코드 처분 계산:
  - 동일 사례가 있으면 그 처분(감점 n점 또는 경고)을 가져온다. 여러 선례의 처분이 다르면 가장 최근 것을 제안하고 차이를 표시한다.
  - 신규 유형이면 처분을 비워 두고 전원 논의로 표시한다.
  - 경고 w회 → max(0, w − 2)
- 기억(Case): 학과, 회계기간, 조항, 사례 유형 태그, 사례 설명, 처분, 판단 사유, 이의 여부
- 감사보고서 초안 (4부 17조): 감사대상과 책임자, 감사 수행 범위, 감사 수행 기간, 총 감사시간과 선임위원 감사시간, 질의 내용과 답변, 감사의견(4가지 평가), 감사인단 서명란
- 감사 후 절차 기한 관리 (4부 19~21조): 보고서 송부는 감사 종료 후 3일 이내, 이의 접수는 송부 후 3일, 답변 전달과 전문 공시는 송부 후 7일 이내
- 감점 기준 목록 공개 (4부 25조): 직전 회계기간까지의 감점 기준을 기억에서 뽑아 감사대상에 제공
- (P1) 감사 품질 확인 (4부 8~12조): 정기감사 최소 20시간, 비정기 10시간, 감사인 1인 2시간 이상, 선임위원 합계가 최소 시간의 1/2 이상

| --- | --- | --- |
| 축제 부스(별도 통장 사용 시) | 사용 전 통장 사본 전달·승인, 수입·지출 전부 또는 수입만 별도 통장 중 선택, 별도 엑셀 장부, 통장사본·과거거래내역서 제출, 비정기감사 요청 여부 결정 | 3부 18~23조 |
| 모든 사업 | 사업번호 부여, 사업개요서('대상'란에 참여 조건, 참가인원은 집행부/전체) | 3부 37~48조 |
| 참가비 사업(MT 등) | 참가비 ≤ 사업 지출, 학생회비 통장으로 수취, 예약금은 이체내역서 보관 | 3부 11·13조, 32조의 2 |
| 물품 판매·공동구매 | 학생회비 통장으로 수취, 수입 구분은 감사위원회 질의 권장 | 3부 6·11·12조, 2부 4.3·5 |
| 세목 표기가 어려운 업체 | 다른 업체 검토, 불가피하면 계산서 6항목 | 3부 35조 |
| 타 학과·단과대 공동 사업 | 단체간거래확인서, 이체내역서 | 3부 30조의 2, 33조의 2 |

| 감사의견 공시 후 | 1개월 안에 감사의견서를 삽입해 제본(3년 보관), 전자 공시(5년, 누구나 접근, 수정 불가) | 3부 69~71조 |

## 5. 그 밖에 맞출 것

- 페르소나: 회계 책임 구분(2부 8). 학생회장은 전반적 책임, 회계 담당은 제한적 책임.
- 공개 페이지 문구: 감사위원회는 징계 권한이 없고, 결과 공고로 의결기구의 판단을 지원한다(2부 9).
- 개인정보: 감사인의 비밀유지 의무(4부 5조)를 재식별 매핑표의 접근 제한 근거로 쓴다.
- 감사자료 원칙이 인쇄·제본·원본대조필(3부 62~65조)이라는 점을 밝힌다. 이 도구는 그 묶음 PDF를 만들어 주고, 전자 제출을 인정할지는 감사위원회 개정 사항으로 둔다.
- 가상 데이터에 넣을 경우:
  - 세목 없는 영수증(계산서 항목 일부 누락)
  - 예약금과 환급
  - 단체간거래
  - 수수료 포함 수입
  - 참가비가 지출을 초과하는 사업
  - 할부 결제, 포인트 적립
  - 근거 비고가 없는 전용 처리
  - 축제 별도 통장 미승인
  - 이미 수검한 증빙
  - 선례가 있는 사례와 신규 사례
  - 경고 2·3·4회
- 성공 지표 교체:
  - 삭제: "점수 ±5점", "등급"
  - 추가: "동일 사례 매칭 일치율", "총 감점 일치", "세목 유무 인식 정확도"
- 도식 2개(아키텍처, 48시간 일정)의 라벨을 위 내용에 맞게 수정한다. 아키텍처의 감사 경로는 "감사 LLM → 코드 검증 → 선례 감점 + 경고 규칙 → 감사인단 확정 → 기억·공개" 순서다.
