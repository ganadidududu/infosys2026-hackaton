# Auditon — 학생회 재정 감사 도구

한양대학교 정보시스템학과 해커톤 출품작 · 주제 **“소 잃고 외양간 고치기 전에”**

학기 전에는 기준안 체크리스트로 준비시키고, 학기 중에는 영수증을 모아 두고, 감사 기간에는 통장과 헝가리안 알고리즘으로 맞춰
기준안 양식의 감사자료를 만든다. LLM이 기준안 원문과 과거 감사 선례로 감사 초안을 쓰면, 감점은 선례에서 코드가 가져오고(4부 23조)
감사인단이 확정한다. 결과는 학생회가 전자 공시(3부 70·71조)하는 학생 공개 페이지로 나간다.

> 모든 데이터는 기준안 양식을 본뜬 **가상 데이터**다. 실제 학생회 데이터는 쓰지 않는다.

## 실행

```bash
./run.sh            # 처음 한 번은 의존성 설치 포함 · http://localhost:8000
```

개발 모드(화면 수정 시 자동 새로고침):

```bash
# 터미널 1 — 백엔드
cd backend && python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000

# 터미널 2 — 프론트엔드
cd frontend && npm install && npm run dev      # http://localhost:5173
```

관리자 화면(`/admin`)의 상단 탭은 3개로 고정이다.

| 탭 | 하는 일 |
| --- | --- |
| **(수입·지출) 내역서** | ① 영수증 OCR·저장 → ② 기중 거래 장부 CSV 올리기(열 자동 매핑, 틀리면 화면에서 수정) → ③ 영수증↔거래 헝가리안 대사 → ④ 학기말 수입/지출내역서 **Word(.docx)** 내려받기 |
| **학기 스케줄러** | 상단 일정 바(회계기간 → 감사 → 송부·이의·공시), 학과 일정 직접 추가·CSV 업로드, 행사별 기준안 체크리스트(권장 기한) |
| **모의 채점** | 지난 감사 기록 박스 + 새 감사 기록 만들기(팝업) → 채점 페이지: 감사자료 슬롯 업로드(회색→초록) → 채점 → 좌 제출 현황 · 중 서류 하이라이트 · 우 점수(100점 만점 = 100 − 총 감점)와 지적 근거 → 감사보고서·공시 |

학생 공개 페이지는 `/`. 시연 순서: 모의 채점 → 새 감사 기록 → **시연용 서류 채우기** → **채점 시작** → 확인 필요·신규 유형 처리 →
감사보고서·공시(송부 → 이의·답변 → 학생회 전자 공시) → 학생 공개 페이지.
처음 상태로 되돌리려면 서버를 끄고 `backend/var/` 폴더를 지운다.

### 모드

| 환경변수 | 기본값 | 설명 |
| --- | --- | --- |
| `AUDITON_LLM` | (없음) = 재생 모드 | `live`로 두고 `ANTHROPIC_API_KEY`가 있으면 감사 LLM을 실제로 호출. 재생 모드는 규칙 기반 모의 응답이며, 검증 단계 시연용으로 ‘인용 불일치’ 1건과 ‘2회 판정 불일치’ 1건을 일부러 섞는다(`backend/audit/llm.py`의 `QUIRKS`) |
| `AUDIT_MODEL` | `claude-sonnet-5-5` | 라이브 모드 감사 LLM 모델 |
| `AUDITON_DATASET` | `tune` | `eval`은 최종 측정 때만 `AUDITON_ALLOW_EVAL=1`과 함께 |
| OCR | 미설치 시 직접 입력 | `pip install easyocr`(또는 `paddleocr`)하면 사진에서 자동 인식. 원본 이미지는 외부로 보내지 않음 |

## 구조

```
backend/
  app/main.py        FastAPI (API + 빌드된 화면 서빙)
  core/kijun.py      감사기준안 원문 → 부·조·항·호 Clause (예: 3부 35조 ③, 2부 6.4)
  ocr/               로컬 OCR 연결, 영수증 텍스트 파서, 자기 검산
  reconcile/         헝가리안 대사(s = 0.5·금액 + 0.2·날짜 + 0.3·이름, δ = 0.3), 부분집합 합(1:N, N:1)
  ledger/            수입·지출 구분, 사업번호, 수입/지출내역서·총거래장부, 규칙 검사, 엑셀 출력
  audit/             감사 패킷, 감사 LLM(재생/라이브), 코드 검증, 선례 처분 + 경고 규칙, 감사의견 초안
  checklist/         행사별 의무(체크리스트 LLM 자리), 조항·인용 검증, 위상 정렬·기한 역산
frontend/src/
  admin/             관리자 화면 6개
  public/            학생 공개 페이지(모바일 우선)
  ui/                판정 색, 조항 칩 → 기준안 원문 서랍, 토스트
data/synthetic/      generate.py · tune/(조정용, 시드 7) · eval/(평가용, 시드 2026, 개발 중 열지 않음)
tests/               경계 테스트: s=0.39/0.41, 동점, 같은 날 같은 금액, 1:N·N:1, 경고 0/2/3/4/7회, 신규 유형, 인용 불일치 등
design/              디자인 시안
```

```bash
python -m pytest tests -q                    # 경계 테스트
python data/synthetic/generate.py            # 가상 데이터 다시 만들기(정답 truth.json 포함)
```

## 설계 원칙 (CLAUDE.md 요약)

- 숫자는 코드가 정한다: 대사, 증빙 유무, 참가비 ≤ 지출, 기한, 감점 합산. LLM이 쓴 숫자는 쓰지 않는다.
- 감점은 선례에서: LLM은 “어느 선례와 같은지”만 답한다. 선례가 없으면 신규 유형 → 감사인단 전원 논의(24조).
- 경고 w회 → max(0, w − 2), 회계기간마다 새로 센다(26조). 등급은 없다. 감사의견은 4부 18조 4가지 평가(양호/미흡 + 사유).
- 판정마다 서류 문장을 그대로 인용. 인용이 서류에 없거나 2회 판정이 다르면 ‘확인 필요’.
- 체크리스트 LLM과 감사 LLM은 분리. 감사 LLM은 체크리스트를 이행 사실로만 받는다.
